Methodology & data notes

How the directory and affinity graph are built, why each scoring weight was chosen, what the score does and does not show, and how the data is refreshed.

Views in this tool: Directory Affinity Network Methodology ← Hub

Where the data comes from

The underlying records are sourced from the State Capacity Ecosystem Database, an open Airtable curated by Henry Tolchard. It catalogs organizations working at the intersection of government effectiveness, civic technology, public-interest research, and democratic capacity. Each row carries eight fields:

  • Org Name — the canonical name of the organization.
  • Primary Segment — one of ten categories: Research, Government, Philanthropy, Fellowships, Community, GovTech, Advocacy, Digital Services & Consulting, Investor, or Training.
  • Secondary Segments — additional tags (Think Tank, University, VC, Impact Investing, etc.).
  • Focus — geographic level at which the org operates: Federal, State, City, or Tribal.
  • Description — a 1–3 sentence summary of what the org does.
  • Funding Model — Philanthropy, Government, Volunteer, Private, VC-backed, etc.
  • Funding Detail — free-text description of specific funders.
  • Website — the org's homepage.

This page is an alternate visualization built on top of that source. Anyone can submit an organization for consideration; submissions are reviewed before being added to the database.

The directory

The directory is a straight rendering of the underlying data. It supports four filter dimensions and a free-text search:

  • Search matches against org name, description, funding detail, and named-funder list.
  • Primary segment is a multi-select on the org's main category.
  • Focus level is a multi-select; an org matches if it operates at any of the selected levels.
  • Funding model is exact-match against the source field.
  • Named funder filters by the funders extracted from the Funding Detail text (see below).

The funding-model filter inherits some inconsistencies from the source data: comma-separated values like Government,Philanthropy and Philanthropy,Government are treated as different categories. These are upstream and can be cleaned in the Airtable.

The affinity score

The network view draws an edge between two organizations when they appear to be working on similar things. The score is a weighted composite of three signals:

score = 0.40 × description similarity
+ 0.35 × segment overlap
+ 0.25 × named-funder overlap
Description 40%
The substance of what the org does.
Segments 35%
The mechanism: how the org operates.
Funders 25%
Theory of change: who believes in this approach.

The framing behind these weights, developed in an iterative back-and-forth with Henry: every signal points at the same underlying question, which is what is this org trying to accomplish, and who else is trying to accomplish the same thing? Segments tell you the mechanism. Funders tell you the theory of change. Descriptions tell you the substance. Together they triangulate purpose more reliably than any single variable.

Description similarity (40%)

The strongest signal, because the description text is where org-specific language lives: phrases like "permitting reform," "legislative capacity," "procurement modernization," or "AI policy." We compute a TF-IDF representation of each org's description and funding-detail text combined, then take the cosine similarity between every pair of vectors.

TF-IDF (term frequency–inverse document frequency) downweights words that appear everywhere ("government," "technology," "policy") and upweights words that are distinctive. Two orgs that both talk about "procurement" will score higher than two orgs that both talk about "policy." Common words and short tokens are dropped before vectorizing.

Segment overlap (35%)

An org's primary plus secondary segments are pooled into a set. We compute the Jaccard similarity between two orgs' segment sets, then add a boost if the primary segments match exactly. The primary boost reflects that an org's primary segment is its core identity, while secondary segments are softer tags. Two Research orgs are more aligned than one Research-primary and one Research-secondary org, even if their segment sets technically overlap.

An earlier version of the score weighted shared focus levels (Federal/State/City) more heavily. We dropped that, because most orgs in the database are tagged with all three, which would have made any pair of broad-focus orgs look artificially close.

Named-funder overlap (25%)

Funders are not extracted from a structured field. They are pulled from the free-text Funding Detail by string-matching against a curated list of approximately 50 well-known philanthropies, foundations, and venture funds active in this space (Schmidt Futures, Open Philanthropy, Omidyar Network, Ford, MacArthur, Knight, Bloomberg, Arnold Ventures, 8VC, a16z, etc.). For two orgs with at least one named funder each, we compute the Jaccard similarity of their funder sets.

If neither org has any extractable named funder, we fall back to a small bonus when their funding-model field matches exactly. This prevents orgs with vague funding text ("philanthropic grants") from being permanently isolated, while still rewarding the specificity of orgs with documented funders.

Limitation worth flagging. Approximately 63 of 304 orgs have at least one named funder detected. The curated list is not exhaustive, and many smaller foundations, family offices, and government grants are missed. Orgs that share an unlisted funder will not light up on this signal — the description and segment scores carry them.

What gets dropped, what gets kept

Pairs with a composite score below 0.05 are discarded entirely. From the remaining pairs we apply two further filters:

  • Absolute floor: edges below 0.10 are not included in the dataset.
  • Per-node degree cap: we walk through the remaining edges in descending score order and keep an edge only if at least one of its two endpoints currently has fewer than 8 kept neighbors. This prevents central hubs (Ford Foundation, ITIF) from collecting hundreds of weak edges that produce a hairball, while still letting them be the most connected nodes.

The published dataset has 304 nodes and 1,681 edges, with a maximum edge score of 0.78 and a median of 0.16. The network view starts at a higher visual threshold (0.18) for legibility; the slider exposes the full 0.10–0.40 range.

What the graph does and does not show

It shows structural affinity: which orgs probably share rooms, attend the same convenings, get covered in the same sentence, and run on similar incentive structures. The strongest edges in the dataset are between orgs that any expert in the field would intuitively put in the same cluster — for example, the four Public-Benefit-Corporation digital-services firms (CivicActions, Nava, Bloom Works, Skylight) all score above 0.75 with each other, and Democracy Fund and Luminate (both Omidyar-Group philanthropies) score 0.76.

It does not show documented relationships. The data does not encode partnerships, joint programs, alumni flows, board interlocks, or co-investments. An edge in this graph is an inference about likely affinity from public-facing descriptions, not an assertion that two orgs are working together.

Refreshing the data

To regenerate the directory and graph from a refreshed CSV, replace data/state_capacity_ecosystem.csv and run the build script:

cd state_capacity_ecosystem
python3 data/build_affinity.py

The script reads the CSV, recomputes TF-IDF vectors and pairwise scores from scratch, applies the thresholds and degree cap, and emits two files: data/graph.json (nodes + edges for the network view) and data/orgs.json (a flat directory bundle). The known-funder list lives at the top of build_affinity.py and can be extended by adding entries to the KNOWN_FUNDERS array; the script automatically rebuilds the funder index on each run.
